# ORBITAL GUARD

**Платформа мониторинга околоземных объектов и предварительного анализа орбитальных данных.**

ORBITAL GUARD — цифровой прототип для NASA Space Apps Challenge. Он получает открытые орбитальные элементы CelesTrak, рассчитывает текущее положение объектов и показывает орбиты на интерактивном 3D-глобусе.

> **Важно:** аналитика сближений в прототипе — описательная визуальная оценка, а не прогноз или предупреждение о столкновении. Не используйте её для принятия операционных решений.

## Возможности

- **3D-мониторинг:** вращение и масштабирование глобуса CesiumJS, отображение объектов и рассчитанной траектории.
- **Каталог и поиск:** фильтрация по категориям, поиск по названию, международному обозначению или NORAD ID.
- **Карточка объекта:** доступные идентификаторы, тип, высота, орбитальные параметры, эпоха и возраст элементов.
- **Свежесть каталога:** источник данных, время загрузки и явное предупреждение при использовании кэшированных данных.
- **Предварительная аналитика:** оценка возраста элементов и расстояний между объектами в один и тот же момент времени.
- **Без фиктивных данных:** при отсутствии каталога отображается ошибка; реальные объекты не подменяются демонстрационными.

## Быстрый запуск

Требуются **Node.js 20.19+** и **Python 3.10+**.

### 1. Установите зависимости интерфейса

```powershell
npm install
```

### 2. Создайте окружение Python и установите зависимости API

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
```

### 3. Запустите API

В первом терминале:

```powershell
.\.venv\Scripts\Activate.ps1
uvicorn backend.main:app --reload
```

### 4. Запустите интерфейс

Во втором терминале:

```powershell
npm run dev
```

Откройте адрес Vite — обычно <http://localhost:5173>.

| Адрес | Назначение |
| --- | --- |
| <http://127.0.0.1:8000/docs> | Интерактивная документация API |
| <http://127.0.0.1:8000/api/health> | Проверка состояния API |

Интерфейс и глобус используют интернет для получения орбитальных данных и картографических тайлов.

## API

| Маршрут | Описание |
| --- | --- |
| `GET /api/health` | Проверка готовности |
| `GET /api/objects?group=stations&limit=2000` | Объекты категории с рассчитанными координатами |
| `GET /api/objects?group=stations&search=ISS` | Поиск по каталогу выбранной категории |
| `GET /api/objects/{catalog_id}/orbit?group=stations` | Точки распространённой SGP4 орбиты |
| `GET /api/analysis?group=stations&limit=2000` | Свежесть элементов и мгновенные расстояния |

Поддерживаются группы `stations`, `active`, `debris` и `rocket-body`. Объекты фильтруются и ищутся в выбранной группе. На карту выводится до 2 000 объектов; размер доступного каталога API сообщает отдельно.

## Источники и точность

- Backend загружает элементы CelesTrak в формате **OMM JSON** и распространяет их на время запроса с помощью **SGP4 / Skyfield**.
- Каталог кэшируется в памяти на 15 минут и сохраняется в `backend/.cache/` для повторного запуска. Если источник недоступен, приложение явно помечает ответ как кэшированный; если кэша нет, API возвращает ошибку.
- Высота рассчитывается по распространённому положению объекта. Возраст элемента показывается отдельно и сам по себе не является оценкой точности.
- Данные GP не дают в этом интерфейсе подтверждённой страны или организации-владельца — эти сведения не угадываются.
- Расстояния между объектами рассчитываются для их положений **в один момент времени** и только в загруженной выборке. Совпадающие или близкие позиции не подтверждают будущую встречу.
- Для анализа вероятности столкновения потребовались бы дополнительные данные, включая неопределённости орбит и ковариации; прототип их не рассчитывает.
